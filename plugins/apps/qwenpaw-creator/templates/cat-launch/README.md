# 非正式发布会

Creator 官方内置固定模板，ID 为 `informal_launch`。选择“非正式发布会”、上传参考图，发送“给这只猫做一个发布会”。支持单图或多图，也可同时上传音频；有上传音频时优先用作 BGM，没有时由单次 r2v 同步生成画面与轻快发布会配乐。模板引导现有 Creator 流程完成读图、分镜、视频、双语包装与 MP4 合成，默认约30秒。生成视频始终铺满项目画布，文字与动效直接叠加在视频内部。

创作规则、字幕样式及封面位于本目录；`video_templates.py` 将 `template.json` 注册为官方内置模板，风格选择器接入 `presentation.ts`，用 `cover.jpg` 展示并置于“默认风格”之后、其他模板之前。固定字幕填充入口为 `backend/services/media_files/informal_launch_template.py`，现有动效设计流程仅在选中本模板时调用它；不修改 Agent 基础 prompt、skill 或通用字幕渲染器。

## 使用

模板随 Creator 插件源码一起提供，不再依赖 `user-templates/` 安装。开始创作时，“默认风格”保持第一位，“非正式发布会”作为第一张官方风格卡紧随其后，使用带文本的猫咪发布会封面，不显示用户模板删除按钮。封面只是风格示例，支持一张或多张参考图。

历史 `user:cat_launch_v1` 选择值仍解析到该官方模板；列表不会重复展示旧用户模板副本，也不会删除用户数据。已有项目保留自身的模板快照，需在修订时明确应用新版规则。

在「通用」场景中新建项目，选择「非正式发布会」。推荐16:9；用户已选9:16等画幅时按该画幅重新构图，不由原照片比例强制决定。上传清晰参考图及可选音频，发送一句需求，不必提供猫名、长提示词、分镜或字幕坐标。继续遵循项目已有执行授权设置。

## 模板内容

参考[猫咪发布会分镜帖](https://www.xiaohongshu.com/explore/6aabd1d1000000001200375f)的完整信息结构，以及[iCat发布会成片](https://xhslink.cn/o/3WvYnjqYEqc)的特征标题、渐变强调、多款搭配与结尾回扣。前者是七页图文帖，后者是约15秒横幅视频。

- **多图 r2v 参考**：逐张读图，明确主身份、补充角度/细节、姿态、造型或场景等用途。按当前模型上限选用所需图片，它们的 exact AssetVersion 同时进入分镜和视频参考链，不能默认忽略第二张图；不同主体的外观不能混合。分镜只提供构图/动作参考，不设置 first frame，不先播放原照背景，不以无身份图参考的文生图替换猫的身份。音频不进入图片参考数组。
- **用户音频优先**：有上传音频时以用户音频作 BGM，用其 exact `source_asset_version_id` 创建 `creation.type=audio`、`role=bgm` 的元素，`script` 留空、`gain_db=0`，沿用现有混音器的音乐床增益。R2V 设 `generate_audio=false`，不再生成另一首配乐。多条音频以用户指定为先，未指定时按素材理解和时长选择合适的一条；音乐过长按成片时长截取，过短复用同一版本接续并用短交叠淡化处理接点，不添加运行时不支持的音频字段。保留用户音乐本身的风格和人声，不用器乐要求替换它。
- **无音频时模型配乐**：默认一个30秒多镜头 R2V 单元，显式设置 `creation.generate_audio=true`，在同一个 `creation.video_prompt` 写入声音设计。模型直接生成贯穿全片的原创器乐配乐：轻快、明亮、干净，清透合成器或拨弦音色、温暖低音与克制鼓点；开场简洁、主体稳定推进、造型揭示适度抬升、片尾自然收束，切镜不重新起乐。少量同步轻音效融入配乐，无歌词、人声或旁白。此分支只使用模型原生音轨，不另建 BGM、TTS 或音效 Element，不要求用户额外上传音乐。模型须支持所需时长、图片参考和本分支的原生音频；能力不足时明确报告，不静默拆段或降级声音方案。
- **单次完整生成的声音说明**：片内10–11个镜头由同一个 R2V Element、同一次模型调用生成，共用一条连续原生音轨。镜头切换不等于多个独立视频的音轨拼接，因此不会遇到逐段生成配乐在衔接处跳变的问题。模板在开场规则、转场规则和声音设计中明确这一前提，要求从 `creation.narrative` 到首次 `creation.video_prompt` 保留音乐说明。用户没有上传音频时，不能将配乐改成只有摄影棚底噪、爪垫或布料声；“无对白、无歌词”也不等于无音乐。这一说明仅用于本模板，不改写 Agent 基础 prompt 或 skill。
- **首次提示词核对**：请求视频生成前回读实际保存的 `creation.video_prompt`，检查完整配乐、曲风/乐器、随镜头推进和片尾收束、切镜不断乐均已写入；只有 `generate_audio=true` 或计划中提到配乐不算完成。有上传音频时则检查真实 BGM 引用、`generate_audio=false`，以及视频提示词没有要求另一首音乐。
- **专属叙事**：读图提取至少三项可见特征，默认规划10–11个镜头，交错呈现亮相、细节、感知或触碰、姿态变化、3–5款搭配及片尾。动作、文案、配色和造型每次为本猫创作；不推断品种、年龄、性格或照片看不清的身体特征。
- **真正的姿势变化**：每镜写出起始姿势、动作过程和结束姿势，至少5种不同身体轮廓、3镜完整全身、2镜可辨认的位移或姿势转换。非造型镜头端坐正面最多2次；眨眼、换装、推近或绕拍不计作新姿势。参考帖中的趋近、伸展、伏卧反应、侧面行走、侧卧翻身等是可选动作语法，按本猫重写，分镜图本身也要画出差异。
- **拍摄指令与观众文案分开**：每镜计划在 `Timeline.description` 内分列 `production_notes`、`audience_brief` 与 `screen_copy`，不新增运行时字段。动作过程、姿态、机位、角度、秒数和留白只进入分镜/视频生成提示词；先把本镜要传达的可见特征或观感提炼成 `audience_brief`，再独立写字幕；`Overlay.creation.text` 与 HTML 只使用独立创作并审稿的 `screen_copy`。不能把“前腿伸长，胸口降低”或“头转三十度后定住”翻译后当字幕。中文先提炼该镜的可见特征或观感，再译英文；副句没有新信息就省略，不为凑版式塞入导演说明。真实的造型数量、颜色和款式标签照常保留。
- **完整双语**：中文主文案与准确英文逐组对应，包括说明、颜色和造型标签。英文不使用固定口号。每个 Overlay 的 `creation.text` 和 HTML 可见文字按相同 DOM 顺序保存。
- **词组与译文校对**：主副句均限4–10个汉字，长句在完整词组之间主动换行；英文采用均衡换行。先整理本片照片确认的中英术语，防止把“加白”等毛色信息拆开或漏译，不将示例里的特征套给其他猫。
- **模板内排版**：片头侧边标题、细节强调、特征与观感卖点、造型总标题与逐款标签、片尾双层文案可以组合。同一区域的主副标题与中英文沿文档流上下排列，造型列表用等宽 Grid；不为每一行文字分别填写绝对坐标。入场移动整个双语组，不让中英文相向穿越，不缩放、模糊或擦除字形。
- **全屏叠字与主体避让**：原视频始终铺满画布，透明字幕直接覆盖片内留白。逐镜核对脸、耳、爪、服装及动作范围，调整整组位置、文案长度与出现时段；空间不足时分时呈现或修正生成构图，不能缩小视频、添加外栏或大面积底板来避让。缺少实片证据时标记待验收，不宣称完成主体检测。
- **造型标签**：生成阶段要求全部造型揭示后固定机位；标签在稳定阅读期出现。实际横移或逐款揭示时，按真实时段延迟标签；没有时段与位置证据时使用画内留白中的紧凑造型列表，不把静态标签错误对应到移动中的猫。

## 字幕文件与渲染契约

选择本模板后，动效设计流程直接填充固定样式，不使用通用 VLM 卡片设计或无 Edit 时的字幕回退。`creation.text` 按顺序保存完整中英组；`creation.prompt` 可用 JSON 选择 `template: "informal_launch"`、`recipe`（hero/detail/paired_callout/look_labels/closing）、`layout`（text_left/text_right/top_left/top_right/collection）、`accent`、`accent_end`，及可选的文字区域百分比 `region` / `header_region` / `label_region`。造型列表先总标题中英，再逐款中英。该入口仅填充传入文案，不编造翻译或主体位置。

完整稿件整批启用后调用现有 `design_motion_overlays`；即使仅有 R2V 而没有 Edit，也会生成版本4固定文档和正确的透明字幕画布。已经正确设计的版本4文档保留，显式指定字幕元素重做时仍使用本模板，避免退回水墨、气泡或通用卡片。

`caption-styles.json` 是 `template.json` 的 `design_floor_body` 中「字幕设计约束」后的 JSON 的可读副本，两份必须一致，并随插件一起分发。

样式包提供 `document_template`、`region_template` 和 `group_template`。Agent 编写本次中文、英文、文字区域、时长与配色；固定模板入口填充并 HTML 转义文字。也可直接提供按本样式填好的版本4文档。HTML 使用现有允许 Agent 写入的 `html_css`，并声明 `template_version: 4`。每个区域只放一个 `region`，内部 `group` 没有独立的绝对坐标；标题换行后，英文和副句自动向下排列。动画由现有渲染器 seek，文档不含脚本、外部资源、随机数或计时器。已有版本化模板文档应保留，不再交给通用生成式字幕重设计。Agent 不能直接写入 `html_js`，本模板不依赖这条受限路径。

横版每镜一个透明全画布 Overlay，可见文字组在文档内定位，防止“局部字幕框再缩放一次”造成字体过小。竖版使用全宽透明文字带，填写其实际像素尺寸；不把横版等比缩成狭长字幕框。中文与英文分别设置字号和行高，英文按词换行；动画在开头完成后稳定停留。`overlay_layouts` 给出左右、上角、造型上下分区等片内文字候选区；视频矩形固定为全屏。这些坐标须按实际主体位置核对，不是新增主体识别器。竖版的文字带也保持透明，不能把原视频缩入中部。

旧模板的 `p` 标签及含 `title/text/caption` 的类名会受到通用渲染器的字号覆盖，窄框和缺失动效还可能触发默认卡片回退。新模板使用 `div.en` 和明确的内部类名，显式保留自身尺寸与6%安全边距，避免重复缩放；现有的文案与渲染检查仍然生效，不修改渲染器。

后期采用整批启用顺序：先把全部字幕和必要的全屏 Edit 作为未启用草稿写齐，再一次启用完整后期，之后请求最终合成。使用 Edit 时停用原 r2v；只叠字时保留原 r2v，保持一条全屏视频底层。现有成片记录或“复用成功”不能替代逐镜文字核对；较早的中间成片可能尚未包含后来增加的字幕。

有上传音频时，R2V 保持 `generate_audio=false`，复用旧的有声视频则通过全屏 Edit 设置 `original_sound=mute`，确保只播放用户 BGM。没有上传音频时，R2V 保持 `generate_audio=true`，使用 Edit 明确设置 `original_sound=preserve`，字幕叠加和最终合成保留模型原声。内置模板更新只影响随后应用模板的项目；已创建项目保存自己的模板与生成提示词。要改变既有成片的模型原生配乐，需把声音要求应用到该项目的 R2V 提示词并按现有制作授权重新生成，单纯更新模板文件或重新叠字合成不会产生新配乐。

## 验证与边界

验收必须看实际 MP4，而不是只看提示词、分镜图、任务成功或缩略图：逐镜检查身份与动作、中文及对应英文、所有造型标签、主体遮挡、碰撞、字号、裁字及音轨。合成出现“回退”“安全动效模板”“文案不一致”等警告时，先修正模板填充结果再导出。模板自身不新增主体检测或视频观察工具，也不能让现有工具接受其不支持的 ArtifactVersion 引用；缺少真实审阅证据时必须明确记录待验收，不宣称自动验证通过。

排版检查覆盖入场中间帧、稳定期、末帧及较小预览视口，并加载现有 Creator 预览的安全 CSS。除了画布边界与主体关键部位避让，还要检查中英文、主副组、相邻标签的字形边界两两相交，以及每个区域实际内容高度；不能把“字都在画布里”当成没有重叠。超预算先改短文案或重新安排信息，不用裁字、省略号或微小字号掩盖。

文字审稿需逐组判断是在向观众传达信息，还是在指导模型执行动作；制作指令即使中英文齐全、字号与边界正常，也不能通过验收。检查不能仅靠禁词或禁止数字，合法的颜色、款式与造型数量应保留。

声音验收按分支进行：上传音频分支核对所选真实音频引用，最终 MP4 确实播放用户音乐且没有第二条原配乐；模型配乐分支试听原始 R2V 和最终 MP4，确认连续轻快配乐与同步轻音效。两者均试听开头、中段、造型揭示和结尾的音量、衔接与自然收束；有音轨不等于合格。声音制作说明不进入字幕。模型配乐未生成时记录失败并修订原生提示词，不用后贴音频冒充模型原声。

验收还要确认视频四边由原片覆盖，没有小框、外栏或底衬；文字直接叠在画面中。生成模型可能偏离构图和时序，因此实际成片的可用留白与信息对应关系需要验收。手工校准既有素材的排版样片，只能证明模板渲染效果；一键流程必须以新项目、原照和短提示词独立验证。

`cover.jpg` 取自已生成的猫咪发布会视频，作为可分发的风格封面；此目录不包含用户原始照片、上传音频、其他测试媒体、项目运行数据或模型凭据。
